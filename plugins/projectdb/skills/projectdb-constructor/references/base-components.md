# Выбор готовых компонентов установленной базы

Использовать при поиске замены собственному коду. Это ориентир по изученной поставке владельца, а не обещание одинакового API любой версии ProjectDB. Перед внедрением сверить файлы текущей базы, входящие данные, вывод без JS и фактическое поведение. Наличие компонента само по себе не делает миграцию полезной.

## Что проверять первым

| Задача | Где искать | Существенные условия |
| --- | --- | --- |
| Формы, отправка, поля и файлы | `module/form2`, `template/include/*.twig.info` | Не заменять includes/grid. Fileupload уже имеет выбор/загрузку/удаление, accept, limit и оформление; не создавать второй загрузчик. |
| Окно и Tab внутри него | `module/dynamic-box/index.twig.json`, `javascript/jquery.modal-tabbing.js` | В изученной поставке dynamic-box уже подключает modalTabbing. Проверить использование перед добавлением второго focus trap. |
| Системная ссылка/действие | `module/html/template/a.twig` | Использовать href, target и data вместо фиксированного адреса в Twig/JS. |
| Меню и дерево | `module/menu/template/index.twig`, `javascript/menu.index.js` | Сохранять базовые данные и build_tree. Поддержка collapse в этом представлении относится к Bootstrap; один атрибут не доказывает наличие нужного плагина на сайте. |
| Полноэкранные фото/видео | `module/photoswipe` | В базе владельца добавлен PhotoSwipe 4.1.3 со стандартным UI и скином; представление, адаптер и тема проекта находятся в одноимённой группе и наследуют ресурсы. Не копировать библиотеку и не менять версию без проверки существующего поведения. |
| Карусель | `module/owlcarousel2` | Структурированные проектные Twig и общий адаптер в группе плагина, библиотечные ресурсы наследуются. Не копировать базовые файлы. |

## PhotoSwipe

В изученной базе владельца `base/module/photoswipe/` содержит PhotoSwipe 4.1.3, стандартный UI, общую JS-оболочку и скин. Наличие и версию сверять с установленным пакетом; это группа общих ресурсов, без готового Twig, универсального контракта `data` и автоматического открытия просмотрщика.

- Библиотека: `javascript/photoswipe.js`, `javascript/photoswipe-ui-default.js`, `javascript/photoswipe-template.js`; стили: `style/photoswipe.css`, `style/photoswipe-default-skin.css`; изображения: `upload/param/default-skin.svg`, `upload/param/preloader.gif`.
- Проектное представление размещать в `domains/<проект>/module/photoswipe/template/<имя>.twig` с соседними `.twig.json` и `.twig.info`; техническое имя — `photoswipe.<имя>.twig`. Обработчик открытия и настроек хранить в `module/photoswipe/javascript/`, оформление сайта — в `module/photoswipe/style/`. Имена проектных файлов выбирать по задаче.
- В `.twig.json` перечислять `javascript` в порядке `photoswipe.js`, `photoswipe-ui-default.js`, `photoswipe-template.js`, затем проектный обработчик; `style` — `photoswipe.css`, `photoswipe-default-skin.css`, затем проектную тему, если она нужна. ProjectDB ищет ресурс сначала в одноимённой группе домена, затем в базе. Оригиналы библиотеки в проект не переносить; относительные пути к базе не нужны.
- Общая оболочка хранится в базовом `photoswipe-template.js` как `PhotoSwipe_Template`; для открытия брать `PhotoSwipe_Template.clone()`, не использовать один изменяемый DOM-экземпляр повторно и не дублировать всю оболочку строкой в обработчике. Файлу нужна jQuery основной оболочки. Проект задаёт классы, значки, локализованные подписи, настройки фото/видео и тему. При уникальной разметке допускается проектный `module/photoswipe/javascript/photoswipe-template.js`: он замещает только оболочку через обычное разрешение ресурсов, библиотека и скин продолжают наследоваться. Сохранять обязательные классы, три `.pswp__item`, контейнеры и элементы UI используемой версии.
- `photoswipe-default-skin.css.json` связывает селекторы с изображениями базового скина. Его не перечислять в массиве `style`; спрайт и прелоадер в домен не копировать.
- Подключать реальное представление галереи. Разметку ссылок, подписи и согласованные данные формирует Twig, обработчик запускает API PhotoSwipe. Для изображений передавать адрес и размеры оригинала. Видео/iframe через HTML-слайды требуют проектной обработки; сам базовый пакет не является видеоплеером.
- При переносе существующей галереи сохранять контракт и поведение, обновлять технические имена всех потребителей. Проверять открытие, масштаб, жесты, стрелки, закрытие без клика по нижележащему элементу и адаптацию; миграция ресурсов сама по себе не требует переписывать работающий обработчик.

Для общих базовых плагинов `readme.md` делать кратким и самостоятельным: назначение, состав, подключение и ссылка на `license.md`. Схему описывать непосредственно, без отсылки «как в другом модуле»; общие инструкции разработки и проверок не дублировать. Названия сайтов и их особенности в базовую документацию не включать. Авторство и полный текст лицензии хранить в `license.md`, не повторяя их во всех собственных описаниях; исходные лицензионные заголовки сторонних JS/CSS сохранять.

## Неполные совпадения

- `form2.pages` умеет обычные GET-ссылки через `data.get_param`, но изученный Twig строит `?параметр=N`/`.` и сам не сохраняет остальные параметры текущего URL. Перед заменой пагинации проверить сохранение фильтра. Подключение include также требует корректного контекста form2; простой цикл уже готовых ссылок не обязательно сложнее.
- `jquery.class-not-empty.js` работает с input[data-class_not_empty] через данные form2. Это не полная замена теме input+textarea, обработке reset и уникальным id/for нескольких форм. Проверять также исходное пустое, но определённое value.
- `field_show` есть у изученных select/select2. Не переносить эту возможность на radio-list без подтверждения его исходным кодом. Не менять тип поля ради использования готового механизма, если это меняет интерфейс и контракт.
- `jquery.tabbing.js` переключает локальные панели, меняет классы и имеет стартовую анимацию прокрутки. Это не замена обычному меню категорий с href и серверной GET-пагинации. `form2.tab` — поле со своим value, а не универсальная навигация сайта.
- Blueimp содержит готовые фото/видео-галереи, preview, controls и fullscreen. Замена согласованного PhotoSwipe требует проверки масштаба, жестов, закрытия, iframe и CSS; считать это миграцией, а не подключением без последствий.
- Базовый Video.js имеет методы и события плеера, в изученной версии загружает JS/CSS с CDN. Он не заменяет автоматически официальный iframe YouTube/Rutube и не всегда нужен обычному native video.
- `absoluteWrapDropdown` рассчитывает/переносит выпадающий блок. Не применять вместо готовой CSS-компоновки и согласованной логики мегаменю только ради сокращения своего файла.
- `form2.map-touch` — поле выбора координат. `ym` — Метрика. Ни один из них не является прямой заменой самостоятельной карте контактов с fallback.
- `window-open` выполняет переход через JS и в изученной версии инициирует click родителя. Для обычной ссылки достаточно href/target; не подменять ими навигацию без необходимости.
- `substr`, dragscroll, lazyload и hyphenate применять только при соответствующей задаче. Не дублировать ими Owl, браузерное loading или CSS overflow/text-overflow.
- Готовые иконочные наборы не гарантируют совпадения с макетом по форме, толщине и пропорциям. Не заменять согласованные SVG только потому, что набор уже есть в базе.

Основные экранные базы конструктора включают штатный `websocket.index.twig` для обмена с бэкендом; модальные базы повторно его не подключают. Это не подтверждает работу серверного соединения в статическом прототипе. Соцавторизацию, push, календарь, декоративные эффекты и аналитику подключать по задаче, без переноса всего перечня плагинов.

## Проверка замены

Сравнить входные данные, начальный HTML, побочные действия, требуемые зависимости и необходимость проектного адаптера. Если полный цикл начинает требовать больше условий, новых библиотек или смены UX, небольшой обработчик владельца может быть правильнее. Итог фиксировать как «уже используется», «прямая замена», «требует адаптации» или «не подходит», с причиной по исходному коду. Не выдавать прочитанную конфигурацию за проведённый браузерный тест.
